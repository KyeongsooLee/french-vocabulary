# Comprehensive v2.6 audit — 2026-09-11

A deeper static/product audit was performed after the initial v2.6 QA.

See:

`QA_AUDIT_v2_6.md`

Important newly identified items include:

- Today queue can allow Seen to starve overdue reviews.
- Seen backlog does not currently reduce new-word intake.
- one `weakSkill` slot cannot represent multiple simultaneous weak skills.
- one global `longReviewPassed` flag can overstate Mastered evidence.
- current `isHardCard()` mixes Weak, manual ★, and historical error ratio.
- Today new words have no explicit A1-A2/B1-B2 scope.
- reverse questions need a semantic ambiguity guard before distractors are made harder.
- sentence recommendation heuristic has identifiable false positives/false negatives.
- local `file://` upgrades have a browser-storage portability risk.
- explicit state/session schema migrations should be introduced before further growth.

Recommended next release: **v2.7 Learning Engine Hardening**.

# v2.7.1 Auto-spelling regression fix

User real-device feedback found that `자동`/mix study never produced typing questions.

Root cause confirmed in code:
- `CORE = [meaning, listening, reverse]`
- automatic `cardSkillForReview(..., 'mix')` chose only CORE skills
- new-word automatic secondary choice contained only listening/reverse

Fix:
- added `autoSpellingEligible`
- added shared `autoSecondarySkill`
- eligible new-word secondary tasks use spelling at ~20%
- due auto reviews allow spelling at ~12%
- non-due reinforcement allows spelling at ~22%
- Weak/core due logic remains prioritized
- spelling is still not part of mastery requirements

Static QA:
- JavaScript syntax: PASS
- card count: 2,866
- card IDs unique: PASS
- explicit spelling mode preserved
- Smart and Custom auto paths both reference the new auto-spelling mixer
